# progress — 프로젝트 진행 로그 생성 / 업데이트

현재 대화 내용을 분석해 프로젝트 폴더의 `progress.md`를 자동으로 생성하거나 업데이트.
세션이 끊겨도 다음 대화에서 "progress.md 읽어줘"로 컨텍스트를 즉시 복원할 수 있게 한다.

## 사용 예시

```
/progress
/progress 10-projects/Monthly Sales League
progress 저장해줘
작업 기록 남겨줘
```

## 실행 단계

### 1. 프로젝트 폴더 감지

인수가 주어지면 그 경로를 사용. 없으면 아래 순서로 자동 감지:

1. `git status`로 변경된 파일 목록 확인 → 가장 많이 변경된 상위 폴더 추론
2. 대화에서 언급된 파일 경로나 프로젝트명으로 추론
3. 감지 불가 시 사용자에게 질문: "어느 프로젝트 폴더에 저장할까요?"

### 2. progress.md 존재 여부 확인

- **없으면**: 신규 생성 (아래 템플릿 사용)
- **있으면**: 기존 파일 읽고 업데이트 모드로 진행

### 3. 대화 내용 분석

현재 세션 대화에서 아래 항목을 추출:

- **완료한 작업**: 실제로 수행하고 마친 것 (파일 수정, 오류 수정, 기능 추가 등)
- **다음 할 일**: 명시적으로 언급된 TODO, 미완성 항목, "다음에 하기로 한 것"
- **미결 요청**: 사용자가 요청했으나 아직 구현 안 된 것, 아이디어 단계인 것
- **결정 사항**: 방향, 데이터 해석, 설계 선택 등 판단이 필요했던 것

### 4. 파일 작성

#### 신규 생성 시 — 템플릿

```markdown
# [프로젝트명] — 작업 진행 로그

> 세션 간 컨텍스트 복원용. 작업 시작 전 이 파일 먼저 읽기.

---

## 프로젝트 개요

- **목적**: [대화에서 파악한 프로젝트 목적]
- **주요 파일**: [핵심 파일 경로]
- **관련 URL**: [있으면]

---

## 작업 이력

### YYYY-MM-DD — [작업 요약]

#### 완료
- [완료한 작업 1]
- [완료한 작업 2]

#### 결정 사항
- [방향 결정, 데이터 해석 등]

---

## 현재 상태

[섹션/기능/단계별 상태 테이블 — 해당하는 경우]

---

## 다음 작업 목록

### 즉시 할 것
- [ ] [작업 1]

### 이후 할 것
- [ ] [작업 2]

### 미결 요청 (세션 유실 방지)
- [ ] [사용자가 요청했으나 아직 미착수인 것]

---

_Last updated: YYYY-MM-DD_
```

#### 기존 파일 업데이트 시

- `## 작업 이력` 섹션에 오늘 날짜 블록 **추가** (기존 이력은 절대 삭제 안 함)
- `## 현재 상태` 테이블 갱신 (완료된 항목 ✅ 처리)
- `## 다음 작업 목록` 완료 항목에 ~~취소선~~ 또는 제거, 새 항목 추가
- `_Last updated_` 날짜 갱신

### 5. 결과 출력

```
✅ progress.md 업데이트 완료
   경로: 10-projects/[프로젝트명]/progress.md
   추가된 작업: N건
   다음 할 일: N건
   → 다음 세션에서 "progress.md 읽어줘"로 컨텍스트 복원 가능
```

## 운영 원칙

- **기존 이력 삭제 금지**: 업데이트 시 과거 기록은 append-only
- **구체적으로 쓰기**: "수정함" 대신 "France YoY -7.3% → -12.2% 오류 수정"
- **미결 요청 반드시 포함**: 사용자가 "나중에 하자"고 한 것도 빠짐없이 기록
- **파일 경로 명시**: 어느 파일을 건드렸는지 경로 포함
- **추정 내용은 표시**: 대화에서 명확히 확인 안 된 것은 `(추정)` 표시 후 기록

## 언제 쓰면 좋은가

- 긴 작업 세션 마무리할 때
- 다음 날 이어서 할 작업이 있을 때
- 대화 중 요청이 많아져서 잊어버릴 것 같을 때
- 새 세션 시작 시 "progress.md 읽어줘"와 함께 사용
