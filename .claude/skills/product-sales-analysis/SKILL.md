# 프로덕트 세일즈 분석 (세일즈 인텔리전스)

러쉬코리아 제품 매출의 **고정 템플릿** 분석 파이프라인. 포맷은 확정되어 있고, 매달 **데이터(원본소스)만 갈아끼우면** 새 숫자로 갱신된다. 새로 설계하지 말 것 — 이미 만들어진 엔진을 돌린다.

## 엔진 위치
`20-operations/product sales/세일즈 인텔리전스/`
- `config.py` 소스/출력 경로(자동탐지) · `slib.py` 공통 규칙 · `deepdive_core.py` 심층 공유 코어(M3·M4가 채널만 바꿔 호출) · `module1/2/3/4/5.py` · `module_summary.py` · `run_all.py`

## 실행 (이게 기본 동작)
```
cd "20-operations/product sales/세일즈 인텔리전스"
python run_all.py
```
→ 같은 폴더에 6개 산출: `M1_카테고리_인텔리전스.xlsx` · `M2_TOP품목_인텔리전스.xlsx` · `M3_리테일_심층.xlsx` · `M4_디지털_심층.xlsx` · `M5_리테일vs디지털_비교.xlsx` · `00_종합_스코어보드.xlsx`
- **저장 전 해당 .xlsx를 Excel에서 닫아야 함** (열려 있으면 PermissionError → 닫고 재실행).
- **데이터 품질 검사가 먼저 돈다**: `run_all.py`는 모듈 실행 전 `validate.py`(4겹 검사)를 호출. 하드(✖)면 중단, 소프트(⚠)면 경고 후 진행. ⚠ 경고(특히 L4 섹션 이동)가 뜨면 사용자에게 각 건이 **의도된 고정인지/교정 필요인지** 확인받고 `slib.SECTION_DRIFT_OK`(고정 유지) 또는 `slib.AYR_BODYSPRAY`/`ALIAS`/`PRODUCT_CAT_OVERRIDE`(교정)에 반영. 상세: `데이터품질-검사.md`. (계기: AYR 바디스프레이 오분류 재발 방지)

## 소스 (매달 사용자가 갱신)
`원본소스/` 폴더에 베이스 파일을 넣으면 `config.py`가 파일명 키워드로 자동탐지. 상세는 `원본소스/README.md`.
- ① 전체뷰/카테고리: 파일명 `중요자료`/`섹션별`, 시트 `섹션별 매출 정리` (M1·종합)
- ② TOP 20: 파일명 `TOP 20` (M2·M3·M4·M5·종합; `Product Sales` 폴더도 폴백 탐지). RETAIL 블록=M3, DIGITAL 블록=M4, 둘 다 로드=M5 비교, TOTAL=종합.
- ※ 분리 이관된 채널 포트폴리오(`../Sales 포트폴리오/`)는 `디지털 채널별 연매출` 파일(바탕화면)을 별도로 씀 — 이 파이프라인 소스 아님.
- 기간(MAT·최근3M·FY 보정)은 **데이터 최신월에서 자동 도출** — 7월 들어오면 FY도 자동 롤오버. 기간 하드코딩 없음.

## 고정된 분석 규칙 (이미 반영됨 — 바꾸지 말 것)
- **제품 식별병합**: 리네임/중량/카테고리 변동 병합(slib `ALIAS`/`norm`). 표시명은 **최신월 현재 이름**(`NEW-`·`[..]` 노이즈 제거).
- **ABC** 0–50%=A·50–80%=B·80–100%=C / **FY** 7–6월, 현재 FY는 진행분+런레이트 연환산 보정 / **ETC·BOOK·SPA·샘플·세트 제외**(OVAL TIN만 유지).
- **LIMITED**: 시즈널(매년 반복)/콜라보(일회성) 구분, 섹션 단위 처리(개별 순증 아님).
- **종합 스코어보드 = 무조건 전사(리테일+디지털 = TOP20 TOTAL 채널)**. PVM 포함 전부 전사. 리테일 단독 심층은 M3, 디지털 단독 심층은 M4(구조 100% 동일, 소스=TOP20 DIGITAL 블록). M5=리테일 vs 디지털 비교분석(채널 결 차이 대조: 종합비교·섹션 채널비중·성장기여 순위비교·제품 채널편중(SUPER MILK 등)·PVM 비교 + **FY26마감·FY27전략 So what 시트** + **시장 레퍼런스 시트**). ⚠ **시장 레퍼런스(시트6)는 정적** — 매월 자동 아님. 분기마다 사용자 명령 시 research-worker로 수동 갱신(module5.py 코드의 `refsec(...)` 텍스트를 새 리서치로 교체). 월간 run_all은 시트0~5·7만 데이터 갱신, 시트6은 그대로 유지. ※ 기존 채널 포트폴리오(자사 vs 제휴·FY27~29 위닝플랜)는 프로덕트 세일즈가 아니라 `../Sales 포트폴리오/`로 분리 이관 — 자기완결 폴더, `python channel_portfolio.py` 별도 실행.
- **심층 공유 코어**: M3·M4는 `deepdive_core.build(channel=...)` 한 엔진 호출. 규칙·레이아웃을 바꾸면 양쪽 동시 반영. 리테일은 리팩터 전후 출력 셀단위 불변 검증됨. 리테일은 섹션·바이럴을 명시 전달(출력 고정), 디지털은 섹션심층 top2 자동.
- **PVM 분해**: ①물량(실수요) ②가격(인상버프) ③신규-단종 ④LIMITED(섹션) → 합=실제Δ 검증. "매출 성장 ≠ 수요 성장" 메시지 고정. (종합=TOTAL, M3=RETAIL, M4=DIGITAL)
- **BCG**(M3): 매출 상위 10개 섹션, "사내 매출 비중(러쉬코리아 내부, 시장점유율 아님)" × 성장률 4분면. 개념 설명·분류 색통일(`slib.style_bcg`) 포함.
- **인사이트는 매출 유의미 섹션만**: 성장률%만 크고 매출·판매량 작은 소규모(전체 12M의 1% 미만 = `config.SIG_SHARE`)는 전략 하이라이트에서 제외. 표엔 남기되 인사이트/리더보드에서 뺌. (예: 메이크업·낫랩·립케어)
- **바이럴 추적(M3·M4)**: 추적 품목은 **사용자 선정**(module3/4 상단 `viral_blocks`의 `_mass_ovaltin`/`_ros` 등). 런레이트 예측 = 최근3M(×4)·최근1M(×12) 유지 시 12M 매출 → 현재12M比·**FY27 타겟 대비 비중 변화**(M3=`FY_TARGET_RETAIL`≈1,000억, M4=`FY_TARGET_DIGITAL`≈470억). 시즌성 미반영 단순 연환산임을 명시. (현재 M4도 리테일과 동일 품목 추적 — 디지털 전용 품목으로 교체 가능)
- **섹션 심층**: 성장기여 상위 섹션을 시트로 (`section_deepdive(섹션, 시트명)`). M3는 명시 `성장기여 1위 (샤워)`·`성장기여 2위 (헤어)`, M4 디지털은 성장기여 top2 **자동 선정**(현재 헤어·바디케어 — 마사지바 급성장 반영). 시트=제품군 표→상위 제품(12M·최근3M 판매량 YoY)→인사이트. 인사이트 규칙: 드라이버/드래그는 **유의미 제품군만**(섹션 2%+) · 드라이버 **성격(시즌성형 vs 상시형, 진폭)** 구분 · **🔥최근월 발화**(직전6M比 급등, 3M YoY와 별개로 포착) · 🚀급상승(최근2M, 시즌플래그) · ⚠핵심 하락은 **단종(slib `DISCONTINUED`) 제외 + 시즌성 점검**(비수기 탓인지 실수요 둔화인지). 전부 데이터 자동 탐지.
- **표현 규칙**(전 파일): 범주 라벨 색 통일(전략 포지션 `slib.style_pos`·BCG `slib.style_bcg`) · 조건부서식 색이 숫자 가리지 않게(연한 톤) · 셀 텍스트 `=`로 시작 금지(#NAME? 오류) · 모든 표·차트에 인사이트 1줄. → `[[feedback_excel_report_rules]]`
- **전략 입력값**: FY 타겟 등 사용자 제공 수치는 `config.py`(FY_TARGET_RETAIL/TOTAL/DIGITAL)에 둠. 갱신 시 거기만 수정. `FY_TARGET_DIGITAL`은 현재 전사−리테일(≈470억) 임시값 — 확정 디지털 타겟 나오면 교체.

## 주의
- **정확도 우선**: 수치는 소스에서 검증(분해합=실제Δ 일치 확인). 사용자가 특정 수치 교정을 요청하면 소스·로직 확인 후 반영.
- 규칙 변경(새 ALIAS·새 제외 등)은 `slib.py`에만 추가하면 전 모듈에 일괄 적용.
- 단일월(예: "7월 한 달만") 분석은 현재 트레일링 윈도와 다른 모드 → 별도 요청 시 기간만 좁혀 처리.
